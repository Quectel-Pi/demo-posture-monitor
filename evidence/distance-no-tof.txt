# 没有 ToF 时「离屏过近」判定的实测数据与修复（2026-10-29）

## 背景
用户提问：摄像头不支持 ToF 测距，原方案（离屏过近）是否会受影响。
结论：不影响原方案（它本来就是趋势法），但暴露两个真 bug。

## 数据

### 修复前：阈值 0.75 在新机位下等于失效
  基准 width_ratio (40cm 处) = 0.3541
  阈值 too_close_ratio       = 0.750  （绝对值，来自旧摄像头 icSpring 的 0.78）
  触发所需倍数               = 0.75 / 0.354 = 2.12 倍
  针孔模型反推距离           = 40 / 2.12 = 18.9 cm  ← 脸贴屏幕

### 修复后：相对基准 + 平滑
  断言 too_close_ratio_rel   = 1.35
  实际阈值                   = 0.354 × 1.35 = 0.478
  对应估算距离               = 29.6 cm  （比校准时近 26%）

### width_ratio 抖动实测（人未移动）
  raw:  0.377  0.424  0.439  0.474  0.509  0.509  0.524 ...
        极差 0.147（±39%），估算距离跟着 43.7cm → 27.8cm 乱跳

  关键点证据（相邻两帧，右肩 x 从 0.37 跳到 0.27，移动 64px）：
    sh_l(0.75,0.58) sh_r(0.37,0.51)  → 肩宽 0.386
    sh_l(0.78,0.60) sh_r(0.27,0.62)  → 肩宽 0.510

  7 帧滑动中值平滑后：0.424~0.440（极差 0.016），距离稳定 32~33cm

## 精度边界（诚实说明）
  单目粗估误差 ±20~30%，来源：
    · 肩宽个体差异 36~45cm（±25%）
    · 转头/侧身时投影缩短
    · 广角畸变（HFOV 常 >90°）
    · 厚衣服
  且 Z 量的是「到摄像头」距离，不是「眼睛到屏幕」。
  要 ±2cm 必须上 ToF（VL53L1X 等，I²C，几十元）。
