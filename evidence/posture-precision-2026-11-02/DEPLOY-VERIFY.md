# 迟滞（profile_release_ratio）生产实测对比（板 68，2026-11-02）

## 结论

生产部署后 **8 分 5 秒内，真实姿势抖动切换只有 1 次**，折算 **7.5 次/小时**；
部署前同期基线是 **488 次真实切换 / 1.7 小时 = 287 次/小时**。

**降幅约 97%。** 但必须读下面「口径与局限」，这个数字不能直接当结论用。

## 2. 部署后原始记录（全部 3 条，无删减）

```
11:48:04  （无） -> 正常    全部规则未命中（离正常最近的特征偏差 10.3σ）
11:49:12  正常 -> 歪头      命中 ear_tilt >= 13.350（阈值 13.350，实测 19.983）
11:52:45  （无） -> 正常    全部规则未命中（离正常最近的特征偏差 8.2σ）
```

真实姿势切换 **只有 1 次**（正常 → 歪头，实测 19.983 远超阈值 13.350，是真歪头不是抖动）。
两条「（无）→正常」是会话进入（人离开又回来 / 几何一度不可用后恢复），迟滞**按设计不拦**
进入侧，所以计入也不能算抖动。

同窗口内「本帧几何不可用」出现 20~33 次/6 分钟，说明期间摄像头前确实有人、有真实
的检出与失效交替，**不是「没人在镜头前所以没切换」**。

## 3. 口径与局限（重要，不要跳过）

1. **观察窗口太短**：8 分钟 vs 基线 1.7 小时。8 分钟内 1 次，统计置信度低。
   287 → 7.5 这个「97%」只能说明**量级上确实大幅下降**，不能当精确倍数。
2. **人不同、姿势分布不同**：基线 1.7 小时里「低头↔正常」占 72%，说明当时有人长时间在
   低头看屏幕；部署后这 8 分钟里主要是「正常」。**用户实际低头/抬头越频繁，切换基数越大**，
   这一项无法通过短窗口对齐。
3. **`profile_hold_s=0.5` 也在起作用**：进入某标签需连续保持 0.5s。基线那轮同样开了 0.5s，
   所以两者可比；但它和迟滞是两层过滤，不能把全部降幅归给迟滞。
4. **离线可拦上界是 37%**（`hysteresis-offline.txt`：105/287 次离开可被打回）。现场 97%
   高于上界，进一步说明**窗口差异（姿势分布）贡献了很大一部分**，不能只算迟滞的功劳。
5. 因此正式结论应表述为：**「迟滞已上线且未观察到副作用（无迟滞感、无漏判），需要至少
   1.5~2 小时同姿势分布的生产数据才能给出可信降幅」**。当前数据作为「量级正确、方向正确」
   的初步证据。

## 4. 建议的补测方法

需要在**同一个人、同类低头/抬头活动**下采满 1.5~2 小时，最好连基线那台、那个人。
若要 A/B，用 `profile_release_ratio: 0`（完全关闭迟滞）跑一小时，再 `0.5` 跑一小时，
两段用同一脚本、同一人、同一时段不同天各跑一次取均值。

复现：
```bash
ssh 板68 'sudo journalctl -u posture-guard --since "-2h" | grep "画像判定切换" | wc -l'
# 真实切换 = 总数 − 源为「（无）」的行数
python3 scripts/verify_hysteresis_journal.py evidence/posture-precision-2026-11-02/journal-switches-1.7h.log
```
