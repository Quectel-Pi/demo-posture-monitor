# 「离屏过近」判据的实测演进（2026-10-29）
#
# 结论：本机无 ToF，不做任何距离测量。该项判的是「肩宽占比相对校准基准的倍数」。
#       早期的「估算距离（厘米）」已按要求移除。

## 1. 为什么不用绝对值阈值 0.75

  width_ratio = 肩宽像素 / 画面宽

  旧 icSpring 直视机位：正常 0.11，坐很近 0.78   → 阈值定 0.75
  现 UGREEN 俯拍机位  ：正常 0.35 ~ 0.50          → 基准 0.354

  触发 0.75 需要 width_ratio / 基准 = 0.75 / 0.354 = 2.12 倍
  针孔模型反推：40cm / 2.12 = 18.9cm  ← 等于要求脸贴屏幕，规则失效

  改为相对：基准 0.354 × too_close_ratio_rel 1.35 = 0.478
  含义：「比校准时的取景近了约 26%」，与机位/FOV 无关

## 2. 为什么必须时间平滑

  人未移动，width_ratio 实测序列：
    0.377  0.424  0.439  0.474  0.509  0.509  0.524
    极差 0.147（±39%），too_close 反复触发/解除

  根因证据（相邻两帧，右肩 x 从 0.37 跳到 0.27，移动 64px）：
    sh_l(0.75,0.58) sh_r(0.37,0.51)  → 肩宽 0.386
    sh_l(0.78,0.60) sh_r(0.27,0.62)  → 肩宽 0.510

  7 帧滑动中值滤波后：0.424 ~ 0.440（极差 0.016）

## 3. 已移除的功能：单目距离估算

  曾实现 Z = K / width_ratio（K = reference_distance_cm × 基准width_ratio），
  界面显示「估算距离 xx cm」。移除原因：
    · 误差 ±20~30%（肩宽个体差异 36~45cm、转头、广角畸变、厚衣）
    · Z 量的是「到摄像头」距离，不是「眼睛到屏幕」距离
    · 现场一眼看到 "28cm / 83cm" 会误以为是测量值
  → 已删除 distance_cm_est / distance_cm_valid / reference_distance_cm 全部代码与配置
