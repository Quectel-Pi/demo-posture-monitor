# 俯视机位（摄像头在显示器上方，人距约 40cm）问题与修复实测
# 2026-10-29

## 现象
用户挪动摄像头到显示器上方并坐到椅子上后：
  * 校准反复失败：「校准样本不足（6 帧 / 8 帧 / 9 帧）」
  * 日志刷：「本帧几何不可用：头肩比例异常（鼻子离肩线太近）」
  * 界面状态长期停在「托腮」「歪头」，几乎每 10 秒一条提醒

## 三个根因 + 数据

### 1. head_gap 门限 0.22 把低头帧全丢了
合格帧实测 head_gap（(肩线y-鼻子y)/肩宽）：
  0.337  0.315  0.295  0.348  0.305
—— 合格帧本来就贴着 0.22~0.35，人一低头就掉到 0.22 以下 → 被判"几何不可用"丢弃。
**被丢掉的正是要检测的低头帧。**

修：posture.min_head_gap 默认 0.22 → 0.08（只挡关键点错检）
效果：校准 28 帧一次通过（原来 6~9 帧失败）

### 2. 托腮判据在桌面场景必然误报
实测（手放桌面打字）：
  wrist.y = 0.984 / 1.010     肩线 y = 0.531 ~ 0.578
  → 手腕比肩线低 95%~109% 肩宽
  但 wrist-鼻子/肩宽 = 1.47~1.59（这个是正常的）
另一批帧 wrist-鼻子/肩宽 = 0.51~0.80 → 触发 <0.95 阈值 → 误报托腮
（模型手腕点左右飘，比值在 0.5~1.6 之间跳）

修：加门控「手腕必须高于肩线 - 0.1×肩宽」，否则 wrist_to_nose=99
效果：腕鼻恒为 99.00，托腮不再误报

### 3. 歪头用的角度公式在俯视下数值不稳定
原式 head_axis = atan2(nose.x - 肩线中点x, 肩线中点y - nose.y)
俯视下分母（肩线y - 鼻子y）很小 → 横向噪声被放大
同一坐姿实测摆动：-48.3° / -33.0° / -18.0° / -9.0° / -1.3° / +8.1°  → ±50°
阈值 18°，等于随机触发

改用耳线（左右耳连线角度），同一坐姿实测：
  169.0  173.7  175.2  175.2  173.1   → 摆动 6°
修：ear_angle_deg 作为歪头主判据；基准存 ear_angle_deg + ear_angle_valid；
    耳朵不可信时退回旧公式

### 4. 顺带：挪了摄像头不会重新校准
BaselineMatches() 只比 camera_id/分辨率/模型 SHA256，同摄像头换位置检测不到。
启动时实测：基准 width_ratio=0.1097，当前 0.40 → 差 3.7 倍却仍判"有效"

修：启动收 20 帧取中位数比对，>1.8倍 或 head_offset_y 差 >0.45 肩宽 → 作废+重校准
日志：
  [WARN] 校准基准已失效：画面里肩宽占比 0.40，校准基准是 0.11（差 3.7 倍）——摄像头或人就位变了
  [WARN] 旧基准会让所有阈值都算偏，现作废并自动重新校准
