# 03 · 坐姿判定规则

## 1. 为什么全部用"相对量"

坐姿判断最容易犯的错是用绝对像素或绝对角度。人不一定坐得离摄像头一样远，
换机位、换分辨率、换摄像头焦距，绝对阈值就全废。

本实现把一切都归一化到**肩宽 `sw` = |左肩 − 右肩|**（实时测得），
所以「离摄像头 1 米」和「2 米」的同一个坐姿会得到同一个指标值。

从 17 个关键点先算 7 个几何量（`rules.measure()`）：

| 指标 | 定义 | 正常范围（实测） |
|---|---|---|
| `shoulder_width` | 双肩欧氏距离 | 视距离而定 |
| `head_drop` | (脖子Y − 鼻子Y) / sw，脖子=双肩中点 | **0.55 ~ 1.1**（坐直） |
| `shoulder_tilt_deg` | `atan2(Δy, Δx)` 双肩连线倾角 | **< 5°** |
| `head_tilt_deg` | 双眼（无眼用双耳）连线倾角 | **< 8°** |
| `hand_to_face` | 手腕到鼻子距离 / sw（仅统计抬到肩线以上、且在头部横向 ±0.9sw 内的手） | **> 0.8**（手在桌面） |
| `lean` | 鼻子相对髋中线的水平偏移 / 躯干长（髋不可见时退化为相对脖子） | **< 0.2** |
| `width_ratio` | sw / 画面宽 | **< 0.55**（正常距离） |

## 2. 六条规则

| key | 中文 | 判据 | 默认阈值 | 配置键 |
|---|---|---|---|---|
| `head_down` | 低头 / 趴桌 | `head_drop < 0.30`（趴桌时 ≤ 0） | 0.30 | `head_drop_bad` |
| `hand_on_face` | 托腮 | `hand_to_face < 0.65` | 0.65 | `hand_to_face_ratio` |
| `lean_forward` | 身体前倾 | `lean > 0.35` | 0.35 | `lean_ratio` |
| `uneven_shoulder` | 高低肩 | `shoulder_tilt_deg > 7°` | 7.0 | `shoulder_tilt_deg` |
| `too_close` | 离屏幕太近 | `width_ratio > 0.62` | 0.62 | `too_close_ratio` |
| `head_tilt` | 歪头 | `head_tilt_deg > 12°` | 12.0 | `head_tilt_deg` |

同帧多条命中时，按 `VIOLATION_PRIORITY` 只报最靠前的一条：
`低头/趴桌 → 托腮 → 前倾 → 高低肩 → 太近 → 歪头`（越靠前越好讲、越明显）。

### 托腮为什么要加"位置过滤"

第一版只用"手腕到鼻子距离 / sw"，结果**手放在桌面、离脸近**也触发。
实测一次就明白了：桌面高度常常和下巴差不多。所以加了两个必要条件：

1. 手腕必须抬到肩线以上：`wrist.y < neck.y + 0.10 × sw`
2. 手腕必须在头部横向范围内：`|wrist.x − nose.x| < 0.90 × sw`

真托腮时手腕在下巴下方 0.15~0.3sw、横向几乎与鼻子对齐，两个条件都成立。

### 低头为什么阈值是 0.30

`head_drop` 是「鼻子比肩膀高多少」（以肩宽为单位）。实测坐直约 0.55~1.1；
略微低头 0.4~0.5；低头看手机 0.25~0.35；趴桌 ≤ 0（鼻子低于肩线）。
取 0.30 作为"明显低头"，配合 2 秒迟滞，误报很少。

## 3. 迟滞状态机（防抖的关键）

原始逐帧判断一定抖。两层保护：

```
命中 → 记录连续命中起点 → 持续 ≥ violation_hold_s(2.0s) 才置 on 并计数 +1
松开 → 保持 on 直到距最后一次命中 > violation_clear_s(1.5s) 才复位
```

外加**关键点 EMA 平滑**（`smooth_alpha=0.5`）和**几何可信度门**（见下）。

## 4. 几何可信度门 `reliable`

空的椅子、靠垫、海报都会被检成 person，骨架一歪就误报。所以先过一道门
（都不严格，只排除"明显不是坐着的人"）：

| 条件 | 阈值 | 拦住什么 |
|---|---|---|
| `shoulder_width ≥ 0.05 × 画面宽` | — | 人太远、关键点散架 |
| `−0.80 ≤ head_drop ≤ 1.80` | — | 鼻子跑到肩膀下、或者远高于头 |
| 框高 `≥ 0.20 × 画面宽` | — | 目标太小 |
| 框 `高/宽 ∈ [0.8, 5.0]` | — | 长宽比不像人 |

不满足就**按"无人"处理**（`present=false`），不产生任何提醒。实测这一条把空场景
的误报从"每分钟闪一次"降到 0。

再加 4 帧迟滞（`EngineState.miss`），人短暂丢失 0.3~0.5s 不会闪成"无人"。

## 5. 提醒策略

| 触发 | 条件 | 动作 | 冷却 |
|---|---|---|---|
| 坐姿提醒 | 连续 `bad` ≥ 60s | 顶部红横幅 8s + 双音提示 + 记 1 次违规 | 90s |
| 护眼（20-20-20） | 每 1200s | 全屏"护眼休息"倒计时 20s | — |
| 久坐 | 连续在座 ≥ 2700s | 横幅 12s | 每 2700s |

### 违规怎么记账（重要）

**每次违规开始就落一行 SQLite，结束时补上时长**，而不是等提醒触发：

```
violation(id, day, ts, kind, duration)
  · 规则 on  -> INSERT duration=0      （此刻"今日违规次数"就已经 +1）
  · 规则 off -> UPDATE duration=秒数
  · 进程退出 -> 把进行中的那条补齐时长（Stats.close）
```

原因：如果等 60s 提醒才记账，用户 59s 就坐正了，这次违规会完全丢失 —— 那"今日违规
次数"就变成了"今日被提醒次数"，没有统计意义。

## 6. 怎么现场标定（换环境必做）

1. 让被测人坐正，看面板指标行（`低头 x.xx · 肩倾 xx° · 头倾 xx° · 前倾 x.xx`）。
   — 或直接看 `status.json` 的 `metrics`。
2. 记录坐正时的值 → 目标阈值取在「坐正值」与「故意做错时的值」之间。
3. 只改 `/etc/posture-monitor/config.json`，重启应用。
4. 用 `headless` 模式看连续输出，比看界面快：

```bash
PYTHONPATH=/opt/posture-monitor python3 -m posturemon.headless --seconds 30
#   t=  3.2s rknn(NPU) 24.6ms persons=1 present=True bad=False main=- bad_dur=0.0s
#          head_drop=0.74 shoulder=2.1
```

## 7. 规则自检（不需要人和摄像头）

```bash
PYTHONPATH=/opt/posture-monitor python3 -m posturemon.headless --selftest-rules
```

用一组合成关键点，逐条验证"正常坐姿不报 + 每种违规单独能报"。
改阈值后先跑它，能挡住明显的回归。
